## Honest limits

- The new loop detector fired 0 times on 7 real days. That is consistent with lane L8's finding that no real identical-call loop occurred that week, but it means precision is unmeasured and recall rests on synthetic cases (unit tests and a synthetic transcript through the adapter). Experiment E3 (labeled sample) is still needed. A "struggling" tier (3 failed calls in a row, any tools) from lane L8's proposal was not added.
- Delivery was verified end to end only against a stubbed `claude` CLI. The real CLI was not asked to resume a session. The queue's new states (`sending`, `unknown`) were exercised by reading the code and by the double-send tests, not by killing the server mid-delivery.
- The live dispatcher was not run against the real model (the headless CLI is currently "Not logged in"), so the offline breaker and retry were checked through unit tests of the helpers, not by a live failure sequence.
- `runTests` in `mergeWorktree` tests the merge result in a scratch worktree that has no installed dependencies, so a project that needs `node_modules` must pass a `testCommand` that sets them up (a junction into the user's `node_modules` was avoided on purpose: deleting through a junction on this machine can delete the target). No UI calls merge, cleanup or prune yet; they are reachable by HTTP only.
- Read endpoints (`/api/state`, `/api/logs`, `/api/stream`) are still open to anything that can reach 127.0.0.1:7787 (D10, not in Q4's scope). `/api/logs` still reads whole files (Q8, not done).
- Not done: Q6 cost correctness (subagents, price tiers, cross-file duplicates, Codex parser), Q7 context gauge, Q8 log tailing, Q9 dead code, hermetic adapter fixtures beyond the new synthetic transcripts, the outbox as a durable table with transcript-based acknowledgement, and all medium-term items (hooks-first drivers, landing queue, attention scheduler, overlap scheduling).
- Line endings: the repository's JS files are CRLF in the working tree on this machine; edits kept each file's own endings.
