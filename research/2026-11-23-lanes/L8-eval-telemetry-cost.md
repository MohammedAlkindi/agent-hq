### 2. ccusage (github.com/ryoppippi/ccusage, commit 40655d4c413b7fc28fc707163ba0d2d489d6c301; source code)
- Files read: `rust/adapters/claude/src/dedupe.rs` (478 lines), `rust/adapters/claude/src/README.md`, `.../usage_wire.rs`, `rust/crates/ccusage-core/src/pricing/rates.rs`, `rust/adapters/codex/src/README.md`, `rust/adapters/antigravity/README.md`.
- Mechanism: scans `projects/` recursively (so subagent files are included); dedupes across files and sessions by message id + request id (Claude Code copies a response into several transcripts); falls back to message id + session + timestamp when there is no request id, and collapses content blocks of one response through the `parentUuid` chain; drops `/btw` sidechain replays that repeat parent usage with a new request id; when duplicates disagree it keeps the main-thread copy, then the larger token total, then fast speed, then cache-write detail (so a zeroed or partial row loses); reads `usage.speed`, `usage.cache_creation.{ephemeral_5m,ephemeral_1h}` and `usage.iterations` (advisor-model usage billed under its own model). Pricing carries input, output, 5m write, 1h write, cache read, long-context tiers (marginal or whole-request), fast/ultrafast/flex multipliers, and time-scheduled rates. The Codex adapter reads `event_msg/token_count` (cumulative `total_token_usage` vs per-turn `last_token_usage`), forked-rollout replay, compaction usage, service tier.
- Evidence: a maintained tool with an issue-driven fix history (notes cite issues #886, #913, #1765, #1799, #2085, #2255); no published accuracy numbers.
- Applicability: it is the reference implementation for what `costOf/feed` is missing: cross-file dedupe, subagent files, max-total-wins, tier-aware pricing, Codex real format. Effort M. Agent HQ is zero-dependency Node, so port the rules, do not import.

### 3. Claude Code bug tracker on usage accounting (github.com/anthropics/claude-code issues #94224, #91775, #84223, #95555, #97908; read through `gh api`)

### 4. Claude Agent SDK "Track cost and usage" and CLI reference (official docs, fetched 2026-11-23: code.claude.com/docs/en/agent-sdk/cost-tracking, /cli-reference)
- Mechanism: parallel tool calls produce several assistant messages that share one id with identical usage, so deduplicate by id; in the SDK stream per-step `output_tokens` is a `message_start` placeholder, so read output from the result message; `total_cost_usd`/`modelUsage` include subagents, `usage` excludes them; `total_cost_usd` is explicitly a client-side estimate, not billing, and each `modelUsage` entry has `costBasis` (list, managed, unknown); cache TTL is chosen per bucket (main conversation vs "everything else" such as subagents, with `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL`), and on a subscription Claude Code drops to 5-minute TTL once you draw on usage credits. CLI: `--max-turns` and `--max-budget-usd` exist for print mode only; the page contains no loop or repetition detection.
- Evidence: vendor documentation, internally consistent with my transcript measurements (main files 100% 1h writes, subagent files 94% 5m writes).
- Applicability: a constant 2x write multiplier will silently go wrong when the account state changes; use `usage.cache_creation.*`. `claude -p --output-format json` gives a per-run cost oracle for the evaluation harness.

### 8. Published precision and recall for loop/stuck detection (arXiv, read through the HTML versions)
- arXiv 2511.10650 "Unsupervised Cycle Detection in Agentic Applications", George et al. (IBM Research), v1 2025-10-31: 1,575 LangGraph stock-agent trajectories, 57 bad cycles (3.6%), authors' own manual labels (labeller and agreement not reported). Embedding cosine above 0.85 alone: precision 0.16, recall 0.91 (267 false positives); repeated-subsequence alone: P 0.30 / R 0.88; structural candidates confirmed by semantic similarity: P 0.62 / R 0.86 / F1 0.72; thresholds were tuned on the same labelled set.
- arXiv 2604.27151 "Step-level Optimization for Efficient Computer-use Agents", Wei et al., v1 2026-04-29: a "stuck" classifier over the last at most 6 steps, labels from GPT-5.2 run 5 times (positive if at least 3 of 5, excluded if 1 or 2), 300 GUI trajectories split 80/20: ModernBERT-base P 91.0 / R 92.0 / F1 91.5; judge F1 92.7; no false-positive rate reported. GUI agents, not coding agents.
- Applicability: a fuzzy-similarity-only rule is the weakest published design (P 0.16 at the same 0.85 threshold the in-repo doc proposes, although that paper uses embeddings, not Levenshtein); stuck labels from an LLM judge with vote-based exclusion is a reusable labelling recipe for the evaluation harness.

### 9. Early-failure prediction for coding agents (arXiv; abstracts and HTML read)
- StopLoss, arXiv 2610.25525 (Liang et al., v1 2026-10-18): small LoRA monitor over the step count and the last 3 action-observation pairs, checks at tool steps 5, 8, 11, threshold calibrated to a nominal 5% false-kill on successful runs; SWE-bench Verified and a 266-task Pro subset, executors GPT-5.6 Luna and Claude Sonnet 4.6 in Terminus-2. Tier AUC 0.56 to 0.62, step-count-only 0.47 to 0.53; false-kill 27.8% on Pro/Luna at the frozen threshold vs 1.0% on Verified/Luna; the paper does not compare against repetition heuristics.
- FailFast / RestartSmart, arXiv 2608.03222 (Wang, Lyu et al., v1 2026-08-04): Qwen3-0.6B monitor on 8 steps, mini-swe-agent, 500 tasks x 11 seeds; at 5% FPR recall 30.5% and tokens saved 20.4% (Qwen3.6-27B), 14.6% to 20.4% across four policies; at 25% FPR recall 68.3% and 49.0% saved.
- "Continue or Restart?", arXiv 2610.35971 (Srinivasan et al., Menzies, v1 2026-10-26): 147,002 traces; within-task AUC 0.50 [0.48, 0.51]; uninterrupted continuation beat restart policies in 216 of 224 budget-threshold configurations.
- Applicability: even trained monitors catch about 30% of failing runs at a 5% false-alarm budget, and within-task prediction is near chance, so a "stuck" alert should be a prompt to look, never an automatic kill.

### 10. "How Do AI Agents Spend Your Money?" arXiv 2604.22750 (Bai, Huang, Wang et al.; v2 2026-04-29; the in-repo "How Do Coding Agents Spend Your Money?")
- Mechanism: OpenHands on SWE-bench Verified, 8 models, 4 runs per problem; cost per round from non-cached input, output, cache creation (5m rate), cache read; runs ranked by cost into four bins and fitted with a mixed-effects model.
- Evidence: the abstract says accuracy often peaks at intermediate cost; the body says it degrades at the highest cost; cache reads are the largest cost category for Sonnet 4.5; output is priced about 80x cache reads. - Applicability: supports showing cache-read cost and an intermediate-cost warning; it does not support the "75 to 85%" number (see Findings).

### 11. Harness/infrastructure variance in benchmarks (primary pages and papers)
- Anthropic engineering "Quantifying infrastructure noise in agentic coding evals" (Segato, 2026-02-05): Terminal-Bench 2.0, same model, harness, tasks; infra error rate 5.8% (1x specs) to 2.1% (3x) to 0.5% (uncapped); uncapped scores +6 points over 1x (p < 0.01) while 1x to 3x is within noise (p = 0.40); SWE-bench with RAM up to 5x: +1.54 points over 227 problems x 10 samples; advice to treat leaderboard gaps below 3 points with skepticism.
- "The Scaffold Effect in Coding Agents", arXiv 2607.22585 (Vats, Golev; v1 2026-06-08, workshop submission): Goose / OpenCode / OpenHands-SDK x Qwen 3.6 Plus / MiniMax M2.5 x 50 Terminal-Bench Pro tasks (300 trials); tokens per solved task 28,142 (Goose) vs 1,147,740 (OpenCode) for Qwen (40.8x), 36,950 vs 1,546,977 for MiniMax (41.9x); pass-rate gaps within a model 0 to 8 points, CIs mostly include zero; turn budgets were asymmetric.
- Epoch AI "Why benchmarking is hard" (2025-12-23): scaffold-only changes move SWE-bench Verified by up to 11 (GPT-5) and 15 (Kimi K2 Thinking) points; run counts and scaffold names not in the text I read.
- METR "Time Horizon 1.1" (2026-01-29): same tasks on Vivaria vs Inspect, GPT-4o 9.2 vs 6.0 min, o3 94 vs 78, Sonnet 4.5 122 vs 164 (wide CIs); task suite 170 to 228; no Claude Code comparison on that page.
- "Benchmarks as Software", arXiv 2611.08417 (Buchanan, Zhou, Linderman, Re; v1 2026-11-05): about 30% of Terminal-Bench 2.0 tasks had issues, repairs raised accuracy by over 10 points; a 20-point harness gap on GPT 5.4 closed when the wall-clock limit was extended.
- Applicability: for Agent HQ the lesson is about its own metrics (record harness, model, limits, tokens per accepted change) more than model choice; and any "model X is better" claim from a leaderboard needs the harness and resource configuration.

### 12. "Why Do Multi-Agent LLM Systems Fail?" (MAST), arXiv 2503.13657 v3 (Cemri et al.; HTML read to 100k of 160k characters)
- Mechanism: grounded-theory taxonomy of 14 failure modes in 3 categories from 1,642 annotated traces across 7 multi-agent frameworks; human agreement kappa 0.88; LLM judge (o1, few-shot) vs humans kappa 0.77, accuracy 94%.
- Evidence: per-mode frequencies, e.g. step repetition 15.7%, no or incomplete verification 8.2%, incorrect verification 9.1%, reasoning-action mismatch 13.2%. No 93% figure and no "rubber-stamping" rate appear in the portion I read.
- Applicability: the way it validates an LLM labeller against humans (kappa, accuracy) is the template for validating the dispatcher's "why it is waiting" labels; step repetition as a named failure class supports having a repeat detector.

### 15. SWE-agent/benchmark family and reliability metric (abstract-level reads)

## Findings

1. VERIFIED. Agent HQ's message-id dedupe is correct and its token counts are exact on a controlled run. In the headless run the adapter reproduced the vendor's `modelUsage` tokens exactly (4 + 71,792 input-side, 187 output, 119,336 cache read). The naive-sum inflation reproduces: 2.48x in dollars, 2.75x output, 2.13x cache read over 7 days; Claude Code's own UI had the same bug at 2.49x (#94224). The in-repo "about 2.5x" note is CONFIRMED.
2. VERIFIED. Agent HQ's dollars are not exact because the price table is wrong in specific places. Haiku 5.5 requests over 100k prompt tokens cost 5x (Agent HQ undercounts that request class by 45% in the known-truth run, and on this machine 862 of 865 Haiku 5.5 messages are above 100k); Fable 5.1 is priced with Fable 5's $1.00 cache read instead of $0.25 (+$67 of $143 for that model in 7 days); `usage.speed === "fast"` is ignored (no fast rows locally); the 1h write multiplier is applied to every write although the transcript says which tier was billed (subagents are 94% 5m). With a tier-aware formula and the official table the known-truth run matches the vendor to the cent.
3. VERIFIED. Agent HQ sees no Codex activity at all and misprices Antigravity. Codex rollouts are date-nested and use `{type, payload}` with `event_msg/token_count`; the adapter lists a flat directory and parses an older shape. Antigravity: Claude models running inside Antigravity are priced with the Gemini fallback ($0.10/$0.40), 4,050 of about 17.6k planner calls carry no model and cost 0 in `costOf`, and the Gemini table is out of date against Google's page (Gemini 3.8 Flash is $0.75/$3.75/$0.075, doubling on 2027-01-01). INFERENCE: for the three priced 3.8-flash variants the API-equivalent number is about 4x too low.
4. VERIFIED. Two systematic gaps in what gets counted: subagent transcripts are never read (the parent measured 17.9% of 7-day cost; my own number with a different basis was 21%), and the same message id appears in two transcripts for 7.7% of ids (resumed sessions), giving a 6.7% overcount when per-file sums are added across files. ccusage solves both (recursive scan; cross-file dedupe by message id + request id).
5. VERIFIED (hazard, not observed locally). Last-row-wins is the wrong tie-break: #95555 documents rows with every counter zeroed; #84223 documents placeholder snapshots (output about 1) in subagent files. In my data no message had differing rows and only 0.1% of subagent messages lacked a final record, so the current version looks clean. Choose the row with the largest token total, as ccusage does.
6. VERIFIED. "Loop thrashing" in the UI is not a loop detector. The rule (`errLog.length >= 3` on a 24-hour buffer, `errors10m >= 3`) fires for any 3 failed tool calls, and its label says "consecutive errors". The Levenshtein-0.85 breaker in `research/2026-11-21-overnight-agent-hq-deep-research.md` section 15.2C is documentation only: no similarity code exists. The parent's 75.6% firing rate versus 3 strict-proxy samples is consistent with my numbers: 60% of sessions have 3 or more failed calls ever, but 0 consecutive identical calls in 7 days.
7. VERIFIED (design survey). Every shipping detector I read is exact-match and small-window: 3 identical calls then ask (Roo, OpenCode), soft 3 and hard 5 (Cline), action-observation 4 / action-error 3 / monologue 3 (OpenHands), budget and timeout caps (SWE-agent, mini-swe-agent, `--max-budget-usd`), 3 reflections (Aider). None uses edit distance and none publishes precision or recall.
8. VERIFIED (published numbers). The only published precision/recall for similarity-based cycle detection reports P 0.16 / R 0.91 for cosine above 0.85 alone and P 0.62 / R 0.86 when confirmed by structure (one LangGraph app, 57 positives, thresholds tuned on the test set). On this machine the in-repo design (Levenshtein above 0.85, 3 consecutive, and identical error output) fires 0 times in 7 days, while the same rule without the error condition fires 76 times of which 73 are healthy work. I cannot compute its precision without positives.
9. VERIFIED. Learned early-failure monitors are weak: 30.5% recall at 5% FPR (FailFast), within-task AUC 0.50 (Continue or Restart), false-kill 27.8% on one Pro cohort (StopLoss). Continuing a run beat restarting in 216 of 224 configurations. This refutes any plan to auto-kill runs on a "stuck" score.
10. VERIFIED. The in-repo "12 tool calls without an edit" brake attributed to `agent-budget-py` is UNSUPPORTED (package not found) and would fire on 22% of turns here (research, review and browsing turns legitimately make no edit).
11. VERIFIED. "Accuracy peaks at intermediate cost" CONFIRMED with caveats (SWE-bench Verified, OpenHands, 8 models; abstract says "saturates", body says "degrades"). "Input tokens are 75-85% of spend" is UNSUPPORTED by arXiv 2604.22750 (it only says input and cache reads dominate, with no percentage); on this machine the input side is 88.3% of API-equivalent spend (cache read 45.6%, write 42.7%), so the direction holds and the range is wrong for this workload. The abstract's "30x" run-to-run range contradicts the body (about 2x), so do not quote it.
12. VERIFIED. "MAST proves 93% rubber-stamping" is UNSUPPORTED: no 93% figure or rubber-stamp rate in the 100k characters of the v3 HTML I read; the closest statistics are incorrect verification 9.1% and no/incomplete verification 8.2% of 1,642 traces, and step repetition 15.7%.
13. VERIFIED. Both Claude Code and Codex already export per-request token and cost telemetry through OpenTelemetry, with request ids, cache-tier splits, subagent ids and a "blocked on user" span; Codex uses the OTel GenAI attribute names. The OTel GenAI conventions are still "Development" status and moved repositories during 2026.
14. INFERENCE. The proposed UTMP schema (research doc section 17.1) duplicates OTel GenAI and lacks the fields that matter for correctness: request id (dedupe key), agent id and parent id, cache tier split, speed, and service tier; it also leaves ambiguous whether `prompt` includes cache tokens (OTel requires it to). A normalized internal record using OTel attribute names plus those extra fields is a better contract than a bespoke schema.
15. VERIFIED. Harness and infrastructure move benchmark numbers by amounts that rival model gaps: 6 points from resource limits alone (Anthropic, Terminal-Bench 2.0), up to 11 to 15 points from scaffold on SWE-bench Verified (Epoch; relayed counts), a 20-point harness gap closed by a time limit (Terminal-Bench 2.1 paper), and about 41x tokens per solved task between harnesses with 0 to 8 points pass-rate difference in a 300-trial study. Harness-model pair is the unit that matters, and cost per solved task is the metric that differs most.
16. VERIFIED. Token spend is a poor productivity proxy (JetBrains, 404 engineers: 39 to 240x spread at equal commits). The dashboard should label cost as "API-equivalent estimate" (the vendor itself calls `total_cost_usd` a client-side estimate) and avoid ranking agents by spend.
17. INFERENCE. Agent HQ's tests do not test telemetry accuracy: `run-tests.js` asserts strings, syntax and structure; the only telemetry assertion for Codex is that a harness name appears. A fixture replay with known-truth totals would have caught findings 2, 3 and 6.

## Recommendations for Agent HQ

R1. Replace the loop rule with tiered, exact-match detectors scoped to the current user turn. Effort S, risk low.
- Tier 1 "possible loop": 3 or more consecutive identical calls (tool name + canonical input) since the last human prompt, shown as a prompt to look (Roo/Cline/OpenCode precedent); Tier 2 "hard loop": 4 identical action-observation pairs or 5 identical calls; Tier 3 "struggling" (low severity): 3 consecutive failed tool calls with no success between (6 events in 7 days here), and never call it "loop". Remove `errLog.length >= 3` and fix the label that says "consecutive". Keep the Levenshtein idea only as a secondary confirmer when the error text is also near-identical, so it adds recall without the 76-vs-0 noise.
- Expected benefit: alert volume from about 75% of active samples to single digits per week. Evidence strength: high for the problem (own measurement, parent's), medium for the design (industry practice, no published precision). Failure modes: legitimate polling (identical `git status`, waits) would trip Tier 1; allow-list read-only polling tools and require identical results for Tier 2. Measure: labelled-sample precision (R4) and alerts per agent-day.

R2. Fix cost accounting in one pass. Effort M, risk low-medium.
- Read `subagents/` files; dedupe across files by (message id, request id) keeping the row with the largest token total; price cache writes from `usage.cache_creation.ephemeral_5m/1h`; add the Haiku 5.5 over-100k tier, Fable 5.1/5.2 and Opus/Sonnet 5.5 cache-read rates, fast-mode multiplier from `usage.speed`, advisor `iterations`; stop returning 0 for unknown models (show "unpriced" and count the tokens); give Antigravity per-model pricing from Google's page with the 2027-01-01 step; rewrite the Codex adapter to walk `sessions/YYYY/MM/DD`, read `event_msg/token_count` deltas and de-duplicate forked rollouts (ccusage's Codex README is the spec).
- Expected benefit: removes a 45% error class (Haiku >100k), a $67/week error on one model, 18 to 21% missing subagent spend, a 6.7% cross-file overcount, and 100% missing Codex coverage. Evidence: verified by known-truth run and local data. Measure: R3 tolerance (within 1% of vendor `total_cost_usd` per run, within 3% fleet-wide against the OTel ledger).

R3. Build a known-truth cost test. Effort S.
- Fixtures: (a) check in a sanitized copy of the truth-run transcript with its vendor `modelUsage` as the expected output (adapter `projectsDir` makes this a 20-line test); (b) 5 to 10 cheap `claude -p --model haiku --output-format json` runs (about $0.03 each) re-run weekly or when `PRICES` changes, comparing adapter cost to `total_cost_usd` per run; include a run with a subagent and one over the 100k tier; (c) synthetic rows for zeroed usage (#95555), placeholder snapshots (#84223), and a resumed copy. Failure mode: the vendor number is itself a client-side estimate, so assert agreement with the list price table, not with the invoice.

R4. Build a loop/stuck evaluation set before tuning any threshold. Effort M.
- Labels: sample alerts and non-alerts stratified by detector, label them (human or the 5-run LLM-judge recipe from arXiv 2604.27151 with votes of at least 3 of 5 positive, 1 or 2 excluded) and report precision with Wilson intervals; about 96 labelled alerts give plus or minus 10 points at 95% confidence (INFERENCE from the binomial). Calibrate thresholds to a fixed false-alert budget on healthy sessions, as StopLoss and FailFast do. Add injected positives (a scripted fake transcript that repeats a failing command; a `claude -p --max-turns` run told to retry the same command) to measure recall. Because strict loops are rare here (0 in 7 days), recall must come from injection, not from field data. Do not wire any detector to an automatic kill (finding 9).

R5. Add a state-detection oracle and replay harness. Effort M.
- A tiny logging hook (`Notification` with `permission_prompt`, `idle_prompt`, `agent_needs_input`, `agent_completed`; `Stop`; `SubagentStop`; `PermissionRequest`; `PostToolUseFailure`) appends timestamped JSONL; compare it to Agent HQ's snapshot stream to compute per-state precision/recall, detection latency (hook time to first SSE push; designed upper bound is the 600 ms debounce plus the 4 s poll) and flapping. For Claude Code's `claude_code.tool.blocked_on_user` spans use OTel when the beta is on. Replay: feed recorded transcripts through `ClaudeAdapter({projectsDir}).scan(now)` with a fake clock to test the 10 minute and 2 hour state thresholds and the 8 minute stuck rule on real data without waiting.
- Reproducible one-laptop workloads: N parallel haiku runs in throwaway repos (about $0.03 each), two sessions editing one file to exercise leases, a tool that sleeps for 10 minutes (stuck), `kill -9` mid-tool, a resumed session (duplicate ids), a transcript above `FULL_READ_MAX`, a truncated last line.

R6. Make the telemetry contract OTel-shaped, not a new schema. Effort M (optional receiver), S (internal record).
- Normalize every harness to one internal record with OTel GenAI names (`gen_ai.usage.input_tokens` as input plus cache read plus cache write, `gen_ai.usage.cache_read.input_tokens`, `gen_ai.usage.cache_write.input_tokens`, `gen_ai.usage.output_tokens`, `gen_ai.agent.id`, `gen_ai.conversation.id`) plus the extra fields Agent HQ needs (request id, parent agent id, cache tier split, speed, price basis). Optionally add a small OTLP receiver so Claude Code (`claude_code.api_request` has `cost_usd` and `request_id`) and Codex (`codex.turn_cost`) can push into a local ledger that becomes the second source for cost reconciliation. Risk: the conventions are in Development status and Claude Code's trace spans are beta; keep transcripts as the fallback. Not adopting a hosted Langfuse/Phoenix stack: they consume the same data and add no accuracy.

R7. Report estimates honestly. Effort S. Show cost as "API-equivalent estimate", show coverage ("N sessions unmeasured", "Codex: no data") instead of zeros, and show cost per accepted change or per merged commit rather than raw spend leaderboards (finding 16).

R8. Use hard budgets for runaway protection, not semantic guesses. Effort S. For scripted or background agents use `--max-turns` and `--max-budget-usd` (print mode, subagent spend counts toward the cap); for interactive sessions alert at a per-session spend and turn-count threshold calibrated on the developer's own history (the p95 of past sessions), and treat "high spend with no commit or edit" as a prompt to look.

R9. Record harness and limits with every cost number (model, harness version, turn/time/budget caps, TTL tier, speed) so that cost-per-task comparisons are valid later. Effort S. Evidence: findings 15 and 16.

## Rejected or not applicable

- Fuzzy similarity as the primary loop trigger (Levenshtein or embeddings): lowest published precision (0.16 at cosine 0.85), 0 firings with the error condition and 73 of 76 healthy firings without it on this fleet.
- ML early-stopping or auto-restart of coding runs (StopLoss, FailFast, AgentStop, EET): trained on SWE-bench-style single-issue runs with small models; published recall about 30% at 5% FPR, within-task AUC 0.50, continuation beats restart in 216 of 224 settings; needs training data the developer does not have. Use only as a future "advisory" with measured FPR.
- "12 tool calls without an edit" brake: unsourced, 22% firing rate here.
- Hosted observability platforms (Langfuse, Phoenix, AgentOps, Helicone) for a one-developer local fleet: they ingest the same transcript or OTel data, have no loop evaluators (Langfuse page says none), and do not fix dedupe or pricing; adding them moves data off the laptop.
- Summing `cost_usd` or token counters from OTel naively without checking `request_id` and temporality: the same duplicate-counting hazards apply.
- Public benchmarks (SWE-bench family, Commit0, Multi-SWE-bench, METR time horizons) as a way to evaluate Agent HQ: they evaluate model-plus-harness solving tasks, not supervision quality. Only pass^k and failure-taxonomy methods (MAST) transfer.
- Treating token spend as a productivity score.

## Gaps and open questions

- Codex and Claude Code loop behaviour: I found no documented loop detector for either; Codex's turn loop was not read (NOT VERIFIED). Claude Code may have undocumented guards.
- No published precision or recall for loop detection on real coding-agent transcripts exists in what I found; the closest numbers are from a LangGraph app and a GUI agent. The only way to get a number for Agent HQ is R4.
- My manual classification of the 6 consecutive-failure events is n = 6 and by one reader. No strict loops occurred in the 7-day window, so recall of any loop detector is unmeasured on field data.
- Antigravity: not verified whether `input_tokens` includes cached tokens, whether "tiered/high/medium" variants share one price, or what the "no model" rows are; Antigravity may not bill per token at all, so "API-equivalent" is a convention.
- Claude Code OTel: unverified whether an http/json OTLP protocol is supported and whether a local file sink has shipped since issue #97908; exact trace-span attributes for `tool.blocked_on_user` were not read in full.
- Fast mode, `inference_geo` and web-search fees were absent in this machine's data, so those multipliers are untested here; `speed` values were all "standard".
- The known-truth experiment is n = 1 (two requests); the tier effect is exact there, but more runs (subagent, over-100k Opus, fast mode) are needed to claim a general error rate.
- The parent measured the subagent share (17.9%) and the loop-rule firing rate (75.6%); my numbers (21%, 60% of sessions) use different bases and are quoted only where noted.
- Harness-versus-model evidence comes from small or secondary sources for several of the largest effects (the 11/15-point SWE-bench gap is from a blog without run counts; the 41x token gap is 50 tasks and 2 open models); none involves Claude Code or Codex as the harness, so the effect of Agent HQ's own supervision on outcomes is untested.
