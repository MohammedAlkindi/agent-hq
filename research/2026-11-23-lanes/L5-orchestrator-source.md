### S1. Claude Squad (smtg-ai/claude-squad), source + 15 issues
- Type/URL/SHA: source code, https://github.com/smtg-ai/claude-squad @ 070eb93 (2026-11-13), v1.0.20 (2026-08-20), 8.9k stars, not archived.
- Mechanism: Go Bubble Tea TUI. Each agent = `tmux new-session` in a git worktree created by `git worktree add -b <branch> <path> HEAD` (session/git/worktree_ops.go L82-113). Status is a 500 ms tick (app/app.go L945-960): hash the captured tmux pane; changed hash = Running, unchanged = Ready; a literal substring such as "No, and tell Claude what to do differently" marks a prompt (session/tmux/tmux.go L244-267). If the tmux server dies, the instance is parked as Paused and can be resumed (session/instance.go L248-263). There is no merge: "push" = `git add .` + `commit --no-verify` + `git push -u` + `gh repo sync`, then a human merges on GitHub (session/git/worktree_git.go L71-121).
- Evidence: issues read: #275, #250, #215 (+ PR #249 analysis), #151, #266, #325, #103, #51, #156, #143, #132, #216, #207, #222, #56. Failure classes: Windows binary non-functional (#275, open since 2026-04-07, no maintainer reply); UI stalls from synchronous subprocess calls (contributor measured, with mock delays, about 107 ms per tick for 1 session and about 1.66 s for 8 sessions on slow disk, relayed from #215); prompt typed before the CLI is ready is lost (#266); stdin race (#325); auto-yes flag did nothing (#151, #222); capture-pane errors after start (#51, #216); maintainers have day jobs (#250).

### S2. Gas Town (gastownhall/gastown, formerly steveyegge/gastown), source + docs + 21 issue bodies
- Type/URL/SHA: source + docs, https://github.com/gastownhall/gastown @ 94cc822 (2026-11-12), v1.2.1 (2026-06-06), 18.9k stars, 1,281 issues total.
- Mechanism: Go daemon + one Dolt SQL server (port 3307) + a tmux session per role (docs/design/architecture.md). Town roles: Mayor, Deacon, Boot (AI watchdog), Dogs; per-rig roles: Witness, Refinery, Polecats (workers in `git worktree`s), Crew. Work and identity live as "beads" rows. Messages: `gt nudge` writes JSON files under `.runtime/nudge_queue/<session>/` that the agent's UserPromptSubmit hook drains at the next turn boundary, because sending keys to tmux cancels in-flight tool calls (internal/nudge/queue.go header; TTL 30 min normal / 2 h urgent; depth cap 50). Landing: the Refinery runs a Bors-style batch-then-bisect queue: batch up to 5 MRs, wait up to 30 s, merge `--no-ff` as a stack on target, test the tip, retry the whole batch once on a flaky failure, bisect on failure (internal/refinery/batch.go L10-35, L90-186). A conflicting MR is dropped from the stack, a conflict-resolution task bead is created, the MR is blocked on it and the queue moves on (default `on_conflict: assign_back`, engineer.go L1563-1680). An exclusive merge slot serializes pushes. Watchdog: daemon heartbeat (3 min) -> Boot -> Deacon -> Witnesses; stuck detection default is ping 30 s, 3 consecutive failures then force-kill, 5 min cooldown (internal/deacon/stuck.go L15-22).
- Evidence (all read): false kill / false stuck: #2707 (a plugin killed 22 sessions across 9 rigs: allowlist built from rig names but sessions use bead prefixes), #4787 (healthy Mayor force-restarted about every 10 min, 50x/day; `doctor --fix` killed every live agent), #4949 (liveness read tmux `session_activity`, which does not advance on pane output; the Witness then sent blind keys into working agents), #4887 (usage-limit wait looks identical to a hang; duration-based detection would kill a healthy worker), #4955 (working dogs flagged hung because LastActive is written only at dispatch), #4890 (idle reaper killed a polecat 1 s after dispatch using the previous session's timestamp), #4964 (reaper closed live patrol molecules), #4329 (spawning a polecat killed a running one), #4613 (heartbeat measures "turn in flight", staleness kill fired 5 to 18+ min late); title only: #3877 (false stuck_heartbeat escalations). Delivery: #4634 (queue silently drops past 50; a P0 sat undelivered about 24 h), #4610 (nudge/Escape recovery destroys unsent operator text; 0 of 9+ typed messages delivered in 30 h). Merge/landing: #4472 (post-merge hook recorded a merge that never happened and deleted the branch; fixed in #4560), #4698 (restart re-primed a polecat on a closed bead -> duplicate conflicting MR). Scale: #3500 (3+ simultaneous polecat spawns crash because all write one shared settings.json with truncating writes), #3068 (77 rigs: bead-prefix collisions), #3938 (32 orphaned dolt servers, about 32% idle CPU), #4165/#4145 (Dolt 70 to 227% CPU), #4820 (dashboard polling piles up bd processes until the process limit). Cost: #3649 (release formula spends users' LLM credits on upstream issues). README claims "20-30 agents comfortably" with no measurement.
- Applicability: the nudge-queue idea and the "merge slot" idea are the reusable parts; the three-tier AI watchdog is the cautionary tale. Touches agent-dashboard.js message queue + worktrees.js merge. See R3, R5. Effort S to M.

### S5. pixel-agents (pablodelucca/pixel-agents), source + CLAUDE.md + 4 issues
- SHA 4dd14d6 (2026-11-09), 10.3k stars. Closest analog to Agent HQ's transcript tailing.
- Mechanism: hybrid. Preferred channel = Claude Code hooks (12 events: SessionStart/End, Stop, PermissionRequest, Notification, Pre/PostToolUse(+Failure), Subagent*, TeammateIdle, TaskCompleted) POSTed to a local Fastify server found via `~/.pixel-agents/server.json`, with a bearer token; install into `~/.claude/settings.json` is consent-gated, backed up once, and retried 3x because Claude Code writes the same file (server/src/providers/hook/claude/constants.ts L35-74). Fallback = JSONL tail with 500 ms polling, scanners at 1/3/30 s, and two heuristic timers (permission guess after 7 s, text-idle after 5 s; server/src/constants.ts L3-27) that are suppressed once hooks deliver. Hook script POST timeout 2 s and it never blocks the CLI (hooks/claude-hook.ts).
- Evidence: its own CLAUDE.md lessons (relayed claims by the project): `turn_duration` records end tool turns reliably (about 98%, the project's number, not verified by me); `fs.watch` unreliable on Windows so pair with polling; a resumed session reopens the OLD transcript so start at EOF; early hook IPC via env vars failed. Issues: #162/#93 (Claude Code 2.1.71+ changed transcript format and agents disappeared), #145 (stuck idle while working), #413 (stale agents: hook rows use synthetic ids; sessions that end without SessionEnd never evicted), #99 (project-dir path encoding mismatch).
- Applicability: direct comparison for adapters/claude.js. Confirms transcript tailing works but needs a hook or registry channel to avoid format drift. See R1, R4.

## Findings

F1. Gas Town "aggressive watchdog killed live working agents": CONFIRMED, VERIFIED (S2). The mechanism is false liveness signals, not short timers: a session-name/prefix mismatch (#2707, #4787), a tmux field that does not track output (#4949), a heartbeat that means "a turn is running" (#4613), quota waits that look like hangs (#4887), activity timestamps not refreshed or inherited from a previous session (#4955, #4890). In-repo wording should change from "aggressive" to "wrong signals, destructive action".

F2. Claude Squad "requires tmux, unsupported on native Windows": CONFIRMED, VERIFIED (S1). It execs `tmux` everywhere (session/tmux/tmux.go) and the shipped Windows binary fails at first session creation (#275, open, no maintainer reply). The "zero visual appeal; no telemetry" parts are opinion/unchecked.

## Recommendations for Agent HQ

R1. Add `claude agents --json` / `~/.claude/sessions/*.json` as the primary liveness + busy/idle source for Claude sessions; keep transcript tailing for content (tool names, cost, text).
- Expected benefit: removes the transcript-inferred "is this process alive and busy" guesswork, covers Desktop sessions, gives pid + procStart to detect pid reuse and dead sessions. Evidence: strong for availability (local probe, docs), none yet for accuracy. Effort S to M (adapters/claude.js; call at the existing 4 s poll or watch the files). Failure modes: research-preview schema drift (docs say use the CLI, not the files); unknown permission-wait coverage; CLI spawn cost 0.74 s per call (so call at most every few seconds, or read files and use the CLI only to cross-check). Measure: log disagreement rate between registry status and current adapter state for a week; count false "stuck" labels before/after.

R2. Put a guard layer on every automatic action in dispatcher.js and the "stuck/loop" labelling: require two independent signals, treat probe failure as unknown, add a mass-change breaker (more than half of at least five sessions changing class in one pass is treated as inconclusive), and never auto-type unless the session is positively waiting with a fresh signal.
- Benefit: avoids the Gas Town class of incident; protects level1 auto-reply. Evidence: strong (S2, S6, S14). Effort S. Failure mode: more "unknown" states shown to the user. Measure: count of auto-actions blocked by the guard and any wrong auto-reply in the audit log.

R3. Harden `mergeWorktree`: verify root HEAD equals target (or merge in memory/with `git merge-tree` when it does not), require a clean tree, run `git merge --abort` on any failure, serialize merges per repo with a promise queue, refuse or rebase when the base moved, and verify with `git merge-base --is-ancestor` before deleting the branch or reporting success (Gas Town #4472).
- Benefit: removes F8 failure modes. Evidence: strong by comparison (S2, S3), the Agent HQ defects are VERIFIED by reading. Effort S. Risk: low. Measure: a test that fires two concurrent merges, one conflicting, and asserts the repo ends clean. Do not build a bisecting queue yet (see Rejected).

R4. Add an optional hook channel for Claude (SessionStart, Stop, PermissionRequest, Notification, SessionEnd) that POSTs to the existing HTTP server, fail-open with a 2 s timeout, consent-gated, with settings.json backup and retry; keep transcripts as fallback and treat 2 minutes of hook silence as the switch back (Orca rule).
- Benefit: instant, exact permission-wait and turn-end events. Evidence: four projects converged (S5, S11, S6, S2), pixel-agents lists early failures with env-var IPC. Effort M. Failure modes: Claude Code also writes settings.json; sessions started before install do not pick the hooks up; Windows `.cmd` hooks add a shell hop and cannot block; Desktop-session support unverified. Measure: time from permission prompt to "needs you" notification before/after.

R5. Message delivery: add a delivery ack and a no-silent-drop rule to the persisted queue (record queued -> sent -> consumed, surface expired items), and evaluate the first-party inbox socket (`messagingSocketPath`) or a hook-drained queue instead of `claude --resume` into a live session.
- Benefit: avoids Gas Town #4634/#4610 and AO #5833 classes; may avoid two processes on one transcript (Claude Code itself added a refusal for opening a conversation already open, 2.1.248). Evidence: strong for the failure classes; the socket route is HYPOTHESIS (needs a Windows test: auth key location, hold behaviour in bypass-mode receivers). Effort M. Measure: percentage of queued messages with confirmed consumption within N minutes.

R6. Fleet resource panel and admission control: show per-session process count and RSS, warn when free RAM is low, stagger new session spawns (the Gas Town #3500 reporter found that spacing spawns about 8 s apart avoided a crash whose root cause was a shared config file), and cap simultaneous spawns. Effort S. Evidence: AO #3921, local measurement (F14). Measure: free RAM floor during a 15-session run.

R7. Make QUEUE_FILE and any shared JSON writes atomic (temp + rename) and read tolerant of partial files. Effort S. Evidence: F15. Not verified in Agent HQ code (I did not open the writer).

R8. Add a "quota-blocked" state and exclude it from stuck/loop heuristics. Effort S. Evidence: F16.

R9. Before pruning or cleaning a worktree, refuse if any live session's cwd is inside it (use the registry from R1). Optionally store checkpoints as hidden refs (T3 Code) instead of commits. Effort S. Evidence: F17.

R10. Reject busy/idle transitions that cannot be tied to a turn in the state machine (T3 #7589). Effort S, depends on adapter design (not read).

## Rejected or not applicable

- Three-tier AI watchdog (Mayor/Deacon/Boot/Witness): costs tokens, produced the false-kill incidents, and a single developer can read a dashboard. 
- Dolt/SQL server as the state store: Gas Town's own issues show zombie servers, CPU burn and connection exhaustion; Agent HQ's node:sqlite WAL is the right weight.
- Stall-timeout auto-kill (Symphony, Gas Town, Orca): same false-positive family; only alert.
- Exclusive file leases as the main coordination layer: Cursor's primary-source result and no harness calling the lease API; keep advisory only. mcp_agent_mail's lease idea has no measured benefit I could find.
- A central integrator/merger agent: Cursor removed it as a bottleneck.
- Bors-style batch-then-bisect queue: no measurement of benefit; at 7 to 19 sessions with few merges per hour R3 covers the correctness gap. Revisit only if merges per hour grow.
- tmux/PTY ownership (Claude Squad, Gas Town, cmux): Agent HQ watches sessions it does not own and runs on native Windows.
- Kanban/issue-board product shape (Vibe Kanban, AO board): no evidence it helps a supervising single user; VK sunset was commercial.
- Screen-scrape status detection: worst drift record (ccmanager, Claude Squad).
- Cloud/mobile relays and sandboxes (Happy, Paseo, Orca remote, OpenHands, Terragon): user is local-first.
- Building a team/mailbox protocol: Claude agent teams already exist (experimental); only recognize their sessions.
